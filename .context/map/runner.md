# runner
Purpose: ervisio-runner, an outbound-only daemon that long-polls the server for Actions tasks and executes each one with the act library from gitea.com/gitea/runner, streaming logs and state back.
Entry points: cmd/ervisio-runner/main.go:dispatch (subcommands register, daemon), internal/runner/daemon.go:Daemon.Run, internal/runner/job.go:executor.execute, internal/runner/report/reporter.go:Reporter, internal/runner/register.go:Register, internal/runner/config/labels.go:ParseLabel, api/runner/v1/runner.proto
Flow: register (errt_ token in body) → State file {id,credential,labels,ephemeral} → daemon: declare labels → pollLoop (capacity slots, FetchTask long-poll, backoff on error) → start → executor.execute: generateWorkflow (single-job payload plus finished placeholders for needs) → PlanJob → PickPlatform(label, runs-on) → act runner with GithubContext built from task.Context → Reporter (logrus hook) batches UpdateLog/UpdateTask → Close sends final result. Heartbeat loop runs separately and carries running ids; the reply lists cancel_task_ids.
Invariants:
- Runner only dials out; all calls are ConnectRPC under APIPath /api/actions/runner (client.go). Only Register uses the registration token; everything else uses "Bearer erun_" from State.
- Job token (erj_) arrives inside Task, is exposed as GITHUB_TOKEN / ERVISIO_TOKEN secrets, never used on the runner service.
- Every secret value is masked by the Reporter replacer before upload; keep new secrets (e.g. ACTIONS_RUNTIME_TOKEN) in the secrets map, not plain env.
- A payload must hold exactly one job; task id and repository are regex-validated before use (path safety).
- Label wire form is name:scheme://image or name:host; host backend runs only if cfg.Host.Enabled, else the job fails.
- Ephemeral runner takes one task then stops fetching.
- Jobs run on a context detached from the daemon ctx; they are cancelled only after shutdown_timeout grace.
- Output limits: key 255 bytes, value 1 MiB (report.maxOutput*), also enforced by the server.
Gotchas:
- act is a patched copy in third_party/gitea-runner (go.mod replace, PATCHES.md): GITHUB_API_URL=<server>/api/v3, GITHUB_GRAPHQL_URL=<server>/api/graphql, step env: wins over the three server URLs, actions/{upload,download}-artifact get GITHUB_SERVER_URL=https://github.com (isGhes check). The server still aliases /api/v1 job-token calls to /api/v3 (jobAPIAlias) for older runners. Dockerfile copies third_party before go mod download.
- go.mod marks gitea.com/gitea/runner, actions-proto-go and others as // indirect although they are imported directly; do not "fix" with go mod tidy without noting it in the report (CLAUDE.md rule 9).
- job.go, workflow.go and report/ are ported from gitea/runner (MIT); keep the license header and upstream behaviours (e.g. isJobStepEntry log routing) when editing.
- Generated protobuf lives in internal/runnerapi/runnerv1 (package path in the proto go_package); regenerate with make generate (buf), never hand-edit.
- act logging goes through logrus; configureLogrus in daemon.go silences/redirects it, and nullLogger stops act writing job logs elsewhere.
- DefaultActionInstance is forced to https://github.com so `uses: owner/action` resolves from GitHub unless the workflow overrides it.
Setup (2026-11-16): daemon auto-registers when the state file is missing (cmd/ervisio-runner/daemon.go loadOrRegister: env ERVISIO_RUNNER_TOKEN | _TOKEN_FILE | <statedir>/registration-token, removed after use) and writes a default config from env (ensureDaemonConfig). register writes the config when missing (config.WriteDefault/Render, defaults.go: DefaultLabels incl. self-hosted/linux/arch, HostLabels, DefaultCapacity = CPUs/2, ExpandLabels for bare names). Server side: ervisio-repo actions runner-token|runner-setup (cmd/ervisio-repo/actionscli.go, actions.OperatorRegistrationToken), install scripts in internal/runnerinstall (go:embed, @@VERSION@@/@@URL@@ templated, mounted in httpapi router at /runner/install.sh|.ps1), release assets via scripts/release/runner-assets.sh. Built-in runner = instance runner named "builtin" (compose profile runner, runner-setup); the UI highlights it.
Device registration (2026-11-16): install.sh without --token runs `ervisio-runner register` with no token → runner.DeviceRegistration (internal/runner/device.go) calls RPC RequestDevice (anonymous, facts + requested name/label names/capacity) and polls PollDevice; server side internal/actions/runnerdevice.go (table actions_runner_devices, user codes from credentials.NewUserCode, limiter s.device: 20 codes/IP/h, wrong-code backoff), approval via v1 /actions/runner-devices/{userCode} (SPA /runner/approve, web/src/pages/auth/RunnerApprove.tsx) with scope label instance|org:<n>|repo:<o>/<n> (Service.ParseScope). Approved poll mints a single_use errt_ (deleted in Register) and returns approved name/labels/capacity; cmd/ervisio-runner/device.go maps label names back to full entries (selectLabels). Client IP reaches the ConnectRPC handler via auth.WithRequestInfo in router.go. `deregister` RPC/subcommand used by --uninstall. Existing config wins over approved labels (daemon declares cfg labels), so --reconfigure deletes config+state first.
Pause/capacity: actions_runners.paused (FetchTask returns empty, rechecked inside the long poll; SetRunnerPaused fires the task hub) and capacity reported in Declare/Heartbeat (HeartbeatResponse.paused is logged by the daemon). Runner.Status = offline|paused|idle|online|busy.
Prune: install.sh (root, Docker backend) writes /usr/local/libexec/ervisio-runner-prune + ervisio-runner-prune.{service,timer} (daily).
Scheduling: pull model, first runner with a free slot and all runs-on labels claims (ClaimActionsJob, SKIP LOCKED); capacity is enforced client-side (pollLoop slots); the server only stores the reported value for display.
Self-update (2026-11-17): admin POST /admin/actions/runners/{id}/update | /update (internal/actions/runnerupdate.go, instance scope, target = server buildinfo version, refused for builtin/ephemeral/self_update=false/dev server) sets actions_runners.update_version (migration 00370); Declare/Heartbeat answers carry RunnerUpdate{version, download_url=GitHub release base}; Declare with version >= target clears it, HeartbeatRequest.update_error(+_version) records a failure once (FailActionsRunnerUpdate). Runner (internal/runner/update*.go): DeclareRequest.self_update = not ephemeral and no /.dockerenv|/run/.containerenv; on request it downloads + sha256-checks (same checksums file/lookup as install.sh, no signature exists for runner assets) into <state dir>/bin/ervisio-runner-<ver>, sets draining (pollLoop stops before the next fetch, in-flight fetch never cut), waits for all jobs without the shutdown timeout, then Run returns *RestartError → cmd daemon Restart: unix syscall.Exec staged path (same PID), Windows renames exe to .old, copies the new one and exits 1 (scheduled task restarts). daemonCmd calls runner.Handoff first: a staged binary newer than the running one is exec'd (older staged ones removed); a failed hand-off is reported and that version is not retried by this process. Runners installed before this feature need one manual install.sh --upgrade.
Related: map/deploy.md (runner images, packaging/systemd), server-side Actions code is not mapped here.
On-demand (2026-11-20): server internal/actions/runnerwake.go (WakeLoop started in wireActions: on tasks hub + every 20s, ClaimActionsRunnerWakes = enabled, not paused, unseen 75s, queued job matching labels/scope; a job another online runner could take counts after 90s) POSTs wake_url with token (sealed, AAD runner-wake:<id>) in wake_header or Authorization Bearer; 2xx → wake_cooldown, refusing 4xx → 600s, other → 60s (wake_next_at). Instance runners only, admin PUT/DELETE/POST /admin/actions/runners/{id}/wake, migration 00450, UI WakeChip/WakeForm in pages/actions/Runners.tsx. Runner: runner.idle_shutdown (checkIdle in heartbeat → draining → Run returns ErrIdleShutdown → cmd idleShutdown runs idle_shutdown_command or writes <state dir>/poweroff-requested, removed at daemon start). install.sh --idle-shutdown D sets the config line and installs ervisio-runner-poweroff.path/.service (root, only a request < 5 min old powers off).
