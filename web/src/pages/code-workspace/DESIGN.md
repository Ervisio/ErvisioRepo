# Code workspace

The approved desktop view is the reference: standalone dark canvas, a 288 px sidebar, a short session header, a scrollable conversation, and a composer capped at 768 px and anchored at the bottom. At 700 px the sidebar becomes a modal drawer. Mobile controls have 44 px targets and respect safe areas. The workspace keeps ErvisioRepo's Figtree type, blue Ervisio mark, and status colors. Its dark surfaces are independent of the site's palette; `--code-*` tokens live in `styles/tokens.css`.

The sidebar shows reachable sessions, server-provided offline recents, and the signed-in identity. Refresh restores offline titles and last activity without browser storage. Only the live list grants access to the transcript or composer. Search filters real titles. Labels repeat the meaning of presence dots without relying on color. Device authorization and account settings stay separate from the workspace; an Android hub session shows linked devices read-only and cannot make changes as a browser account.

Only live PC sessions have a transcript; only their owner has a prompt composer. Cached transcript state is transient and hidden when a session becomes unreachable. New session offers only linked PCs that advertise projects approved for Remote and opens the new session once it appears in the live list. In the same stacked form, projects are grouped and filterable by source: local, ErvisioRepo, or GitHub. The account catalog provides repository names and provider status; entries without a matching live checkout on the selected PC are visible but disabled. Refresh repositories after approving a new checkout on the PC. Local projects remain available without the catalog. When exactly one separate checkout is granted, it is selected by default; an existing checkout always requires an explicit choice. The dialog shows progress while the PC prepares the checkout and creates the session. Creating, sending, and interrupting require explicit actions; an ambiguous outcome triggers a read but never replays the mutation.

Sharing uses the same dialog surface on desktop and in the Android hub. The sidebar opens received and owned shares and shows account-bound invitations with an explicit Accept action. Invitation codes remain optional. The owner shares a live session from its header, selecting visible people or organizations they manage from the scoped directory and explicitly consenting to the history range. Shared sessions use the existing transcript column without the prompt composer. Proposals and review work while the PC is offline; recorded approvals do not execute. An owner can load an approved proposal as an unsent draft only in its matching live session and must explicitly submit it. Transcripts, proposal drafts, and invitation codes are not persisted by the workspace.
