# Shared Todo

Variant Studio `002-shared-todo`, decision `0a7c5ea5ff33`: **A — Sezioni in fila**. The user chose a single vertical list with every category visible over a category index or separate open/completed blocks. [GitHub task lists](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/about-task-lists) informed the checkbox rows and completion count; [Todoist sections](https://www.todoist.com/help/todoist/features/introduction-to-sections-rOrK0aEn) informed the ordered section headings and their action menus.

Variant Studio `002-todo-overview`, decision `2d4f6a0c1b9d`: A, with a correction to keep the repository page intact. Files, README and the original metadata sidebar keep their existing breakpoints and widths. The only addition to the Code toolbar is a `ToDo 3/12` button that opens a dialog; it never reserves a column. The organization panel sits below languages in the existing aside. Its folded state shows the count and disclosure only; the preference belongs to the viewer.

The panel uses `--surface`, `--bg`, `--line`, `--ink2`, `--accent`, and `--acc-fill`, with no palette overrides. Keep the open title centered, add 16 px of internal space on the organization card and distinguish the category text field from its dialog with both fill and border. Use native checkboxes with clickable labels, a compact progress count, Radix menus for move/edit/delete, and an inline quick-add form. An attributed completed task shows a linked avatar with a name label and an initials fallback; historical tasks without attribution stay unmarked. On mobile, the quick-add form wraps and primary controls grow to 44 px.

The React component is `web/src/pages/todo/SharedTodo.tsx`; `todo.css` scopes its layout and `todo.json` holds EN/IT copy. A deleted category leaves its tasks uncategorized. Save conflicts refresh the list and require reopening stale edit and delete dialogs rather than overwriting concurrent changes.
